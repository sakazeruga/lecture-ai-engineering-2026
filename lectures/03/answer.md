# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
  第1回の `app.ask` は用語集を見ずに答えるため、「3レベル」を講座の定義（基礎・実装・発展、どれか1つで完了）と違う内容で答えていた。エージェントは「3レベル」の質問で `search_glossary('3レベル')` を引き、全6回とも「基礎・実装・発展、どれか1つで完了、原則採点なし」と用語集どおりに答え、最後に第1回を示した。「LoRAとQLoRAの違いは？」でも先に `search_glossary` で用語集を引き、その定義に沿って答え、最後に「関連する回：第2回」と示した。
- `--trace` で見えたツール呼び出し（ツール名と引数）：
  `search_glossary({'query': 'LoRA'})` → `search_glossary({'query': 'QLoRA'})` の順に、用語を1つずつ2回呼んだ。「第2回の内容から確認問題を1問出して」では `make_quiz({'lecture': 2})` が呼ばれた。
- 1つの質問での LLM 呼び出し回数（`requests`）：
  どの質問も 2 回（ツールを呼ぶ判断で1回、ツールの結果を見て回答を作るので1回）。同じターンで複数のツールをまとめて呼ぶので、検索が2回でも `requests` は 2 だった。
- 追加したツールと、docstring に書いた説明：
  `make_quiz(lecture: int)`。docstring には「指定した回の用語から確認問題を1問作り、問題と答えを返す。『第2回の確認問題を出して』のように、復習用の問題を求められたときに使う。返り値の answer は利用者にすぐ見せず、回答を受けてから答え合わせに使う」と書いた。用語がない回（第0回など）は、用語がある回の一覧を返す。`--list-tools` に表示され、`uv run pytest -q` は 15 passed。実行では、モデルが答えを伏せたまま「ファインチューニング」の意味を問う問題を出した。

## 宿題

- 取り組んだレベル：基礎
- やったこと：
  `lectures/03/run_basic.py` で、元の設定から1か所だけ変えた条件を作り、同じ質問を `--trace` と同じ形で記録した（モデルは `gemini-3.5-flash-lite`、質問2つ×各条件 2 回）。結果は `lectures/03/results.json`。
  - `baseline`：元の `INSTRUCTIONS` と docstring
  - `no_search_rule`：`INSTRUCTIONS` から「必ず search_glossary で用語集を確認する」の行を消す
  - `bulk_query`：`search_glossary` の docstring の「query には調べたい用語を1つだけ入れる」を「まとめて入れる」に変える
- 結果（質問「LoRAとQLoRAの違いは？」）：

  | 条件 | ツール呼び出し | `requests` | 入力トークン | 出力トークン |
  |---|---|---:|---:|---:|
  | baseline | `search_glossary('LoRA')`、`search_glossary('QLoRA')` | 2 / 2 | 1444 / 1444 | 222 / 198 |
  | no_search_rule | `search_glossary('LoRA')`、`search_glossary('QLoRA')` | 2 / 2 | 1396 / 1396 | 226 / 234 |
  | bulk_query | `search_glossary('LoRA QLoRA')` の1回 | 2 / 2 | 1139 / 1139 | 203 / 225 |

  質問「AIE2026の講座の宿題にある「3レベル」とは何ですか？」：

  | 条件 | ツール呼び出し | `requests` | 入力トークン | 出力トークン |
  |---|---|---:|---:|---:|
  | baseline | `search_glossary('3レベル')` | 2 / 2 | 1031 / 1031 | 134 / 132 |
  | no_search_rule | `search_glossary('3レベル')` | 2 / 2 | 983 / 983 | 164 / 148 |
  | bulk_query | `search_glossary('3レベル')` | 2 / 2 | 1033 / 1033 | 149 / 147 |

  回答の内容（LoRA は重みを固定して低ランク行列だけ学習、QLoRA はベースモデルを 4 ビットに量子化して LoRA を行う）と、最後に第2回を示す点は、3 条件とも同じだった。「3レベル」は、どの条件でも1回検索し、全6回とも用語集どおり（基礎・実装・発展、どれか1つで完了）に答えた。bulk_query の 2 回目は API の 503 で2回失敗し、3回目に成功した。
- 気づき・疑問：
  - 「必ず検索する」の行を消しても、2 回とも検索してから答えた。`search_glossary` の docstring にも「答える前に使うこと」と書いてあるので、指示が2か所に重なっていて、1か所消しただけではふるまいが変わらなかったと考える。指示を消して効果を見るには、docstring 側も合わせて確認する必要がある。
  - docstring を「まとめて入れる」に変えると、検索が1回にまとまり、入力トークンが約2割減った（1444 → 1139）。ツールの説明文の1文で、呼び方と費用が変わることを確かめられた。ただし、まとめた検索語は用語集の部分一致に頼るので、ヒットしない語が混ざると取りこぼす可能性がある。今回は2語とも当たった。用語が1つの質問（3レベル）では、まとめる指示の影響は出なかった。
  - 回数は各条件 2 回、質問は 2 つと少ないので、傾向として言えるのはここまで。
  - AI ツールとして Claude Code を使い、`make_quiz` と比較スクリプトの実装、この文章の下書きを行った。実行は自分の PC で行った。
