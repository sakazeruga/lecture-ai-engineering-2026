  - 「オフィスアワーは事前予約が必要ですか」：予約の要否に触れず、オフィスアワーの日時を `needs_review: false` で答えた
- 知識を問う質問（セクション 6）の結果（学習前の分類 → 学習後の分類）と気づいたこと：

  | 担当教員の名前は何ですか | `format_error` → `needs_review` |
  | 次回の講義のテーマは何ですか | `format_error` → `needs_review` |

  FAQ に無い 3 問のうち 2 問は確認を求めたが、「最終課題の締切」は「課題の提出期限」と同じ文で断定した。形式は整っていても、似た項目があると根拠があるものとして答えてしまう。対照の問いは FAQ にあるので、`asserted` が正しい。なお、`result.json` の `FAQ にある` はこの問いでも `false` と出ている。これは `gold` の質問文との一致で決めているためで、FAQ に載っていないという意味ではない。

## 宿題

- 取り組んだレベル：基礎
- 変えた設定やデータ：
  `num_train_epochs` を 20 から 10 に変えた（40 ステップ → 20 ステップ）。ほかの設定は同じで、変更後はセッションを再起動して上から実行した。各回の `result.json`、`eval_before.json`、`eval_after.json`、`train_log.json` は `lectures/02/results/` に置いた。
- 結果（比較表や数字）：

  | 指標 | 20 エポック（元の設定） | 10 エポック |
  |---|---:|---:|
  | `format_rate` | 1.000（21/21） | 1.000（21/21） |
  | `content_rate` | 0.905（19/21） | 0.857（18/21） |
  | `both_rate` | 0.905（19/21） | 0.857（18/21） |
  | 最終 loss | 0.0139（40 ステップ目） | 0.0981（20 ステップ目） |
  | 学習時間 | 233.8 秒 | 113.4 秒 |
  | `needs_review` の一致 | 19/21 | 20/21 |
  | 根拠なしの質問に断定 | 2 問 | 0 問 |
  | 根拠ありの質問に確認要求で逃げた | 0 問 | 1 問 |
  | `needs_review` は合うが必須語句が無い | 0 問 | 2 問 |
  | 退行 | なし | なし |

  最終 loss は `train_log.json` に最後に記録された値、学習時間は同じファイルの `train_runtime`。`needs_review` の一致は `eval_after.json` の出力と正解から数えた。学習前の評価は両方とも同じ出力で、`format_rate` 0.095、`content_rate` 0.000 だった。

  10 エポックの失敗：
  - 「PDF 以外でも出せますか」：根拠ありの質問なのに `needs_review: true` で確認を求めた
  - 「成績はいつ出ますか」：`needs_review: true` は合っているが、必須語句の「確認」が無く、「必ず質問に答えてください」という文になった
  - 「参考文献の書き方に指定はありますか」：`needs_review: true` は合っているが、FAQ に無い「参考文献」欄があるかのように答えた

  最初の 10 ステップの loss は両方とも約 1.56 で、20 エポックの回でも 20 ステップ目には 0.085 まで下がっていた。そこからさらに 20 ステップ学習しても、正解数の差は 1 問だった。

- ファインチューニングが向く場面・向かない場面についての考察：
  - 向く場面は、出力の形式や文体をそろえたいときだと考える。今回はプロンプトで JSON を指示しても 2/21 しか守れなかったが、14 件の教師データを 2 分ほど学習すると 21/21 になり、10 エポックでも形式は十分に身についた。
  - 向かない場面は、根拠の有無の判断や、事実の追加を任せたいときだと考える。今回は形式が 100% になっても、最終課題の締切のように似た項目があると断定した。頻繁に変わる情報も、更新のたびに再学習が必要になる。講義で紹介された研究でも知識の追加は RAG が上回っており、FAQ の内容を正しく答えさせるには、検索で根拠を渡す方が向くと考える。
  - loss と判断の良さは一致しなかった。20 エポックは loss も `content_rate` も良かったが、失敗はすべて根拠なしの断定だった。10 エポックは `content_rate` が低いものの、断定は 0 問で、失敗はすべて確認を求める側（`needs_review: true`）だった。講座の FAQ では誤った断定の方が害が大きいので、用途によっては 1 つの数字だけで「良い」とは言えない。
  - `content_rate` は語句の有無で判定するので、文面の崩れを見逃すこともある。10 エポックの「この FAQ には記載がありません。必ずに確認が必要です。」は文として不自然だが、合格になった。数字に加えて出力の原文を読む必要がある。
  - ただし、各設定 1 回ずつ、評価は 21 問で、1 問の差が約 4.8 ポイントになる。seed を固定しても GPU 上の学習は完全には再現しないので、エポック数を減らすと断定が減るとまでは言えない。今回の 1 回の結果として報告する。
